# ENB対応の計画（Skyrim 2011 LE 1.9.32・通常版）

作成 2026-11-21。作業ブランチ `claude/laughing-cannon-fvpznk`。目標：Codexがビルドし、すぐiPhoneで有名なENBプリセットを一通り検証できる状態まで。性能の目標は30 fps前後（所有者の指定）。

参照：[開発状況](STATUS.md) · [MOD管理の設計](MOD_MANAGEMENT_DESIGN.md) · [描画の経路](SOURCE_AUDIT.md) · [色調の試作](../experiments/d3d9-present-grade/README.md)（`codex/first-wave-apple-check`） · [後処理の試作](../experiments/d3d9-postprocess/README.md)（同）

## 1. 方針

ENB本体（`d3d9.dll`）は動かさない。所有者のプリセット（`enbseries.ini` と `enbseries/*.fx`）を読み、アプリ内の後処理エンジンで実行する（ENB互換の後処理）。理由：ゲームは事前にARM64へ変換し、描画はD3D9 → DXVK → MoltenVK → Metalで動くため、実行時にWindows用x86のD3D9差し替えDLLを持ち込めない。ENB本体はソース非公開で、その内部（ゲームシェーダーへの介入など）はここから再現できない。

原則（MOD第一弾と共通）：

1. 既定でオフ。オフのときは従来の経路と画素が一致し、追加の描画やコピーを行わない。
2. ENB本体、プリセット、`.fx` はGitHubへ入れない。試験は自作の `.ini` と `.fx` を実行時に生成する。
3. 対応できない構文・変数・テクスチャは、成功に見せかけずに、名前と原因を日英で一覧に出す。
4. 毎フレームの処理は予算を持つ。超えたら品質を段階的に下げる（§6）。
5. 診断行は数値だけ。パス、ファイル名、プリセット名は送らない。
6. 試験を無効化・スキップして通さない。所有者の入力が必要な試験は環境変数があるときだけ実行する。

## 2. ENBの構成要素と扱い

| 要素 | 役割 | iOS版 |
| --- | --- | --- |
| `d3d9.dll`、`d3d9_*.dll` | ENB本体 | 読み込まない。検出して表示する |
| `enblocal.ini` | ENBoost（メモリ）、FPS制限、エンジン設定 | 無視（ENBoostは不要）。FPS制限は既存設定に任せる |
| `enbseries.ini` | 各効果のオン／オフと数値。`[…]` ごとの節。昼・夜・室内・天候ごとの値 | 読み取る（中心の入力） |
| `enbseries/enbeffect.fx` | 最終合成、トーンマップ、色調 | 実行（L2） |
| `enbbloom.fx`、`enblens.fx`、`enbadaptation.fx` | ブルーム、レンズ、明るさの順応 | 実行（L2） |
| `enbdepthoffield.fx` | 被写界深度 | 実行（L3、深度が必要） |
| `enbeffectprepass.fx`、`enbeffectpostpass.fx` | 前後の追加処理（シャープ、粒状感など。作者が追加） | 実行（L2） |
| `enbpalette.png`、`enbbloom.png` など | 画像の入力 | 読み込む（PNGのデコードはアプリ内に既存の部品を流用できるか要確認） |
| SSAO、反射、影、肌の表現など | ENB本体の内部実装 | 対象外（L4。必要なら別計画） |

## 3. 段階

| 段階 | 内容 | 状態（このブランチ） |
| --- | --- | --- |
| L0 | ENBパッケージの認識、プロファイルでの選択、診断。ENB本体を読み込まない旨の表示 | 実装 |
| L1 | `enbseries.ini` の色調・トーンマップ・彩度・コントラスト・ビネットなどを、固定シェーダー1回の全画面描画で再現 | 数式と数値の変換を実装、描画への接続はCodex |
| L2 | `.fx` のtechnique／passの解析、変数とテクスチャの互換層、事前コンパイル | 解析・互換層・パス計画を実装、DXVK／Metalでの実行はCodex |
| L3 | 深度を使う効果（被写界深度、霧、SSAO相当） | 要求の検出と計画のみ実装、取得はCodex |
| L4 | ゲームシェーダー側の効果 | 対象外 |

## 4. 動かし方（実行時の流れ）

1. 起動時：プロファイルのENBプリセットを固定する（`enb` の選択、MOD機能と同じく起動時に固定）。`enbseries.ini` を解析し、`enbseries/*.fx` を前処理して、効果の一覧とパス計画を作る。
2. 事前コンパイル：すべての `.fx` を起動時（ゲーム開始前）にvkd3d-shaderでSM3へコンパイルし、結果を診断に出す。コンパイルできないものは、その効果だけ無効にして理由を表示する。ゲーム中の初回コンパイルによる詰まりを避ける。
3. 毎フレーム（Presentの前、HUDの前が理想）：
   1. 場面画像を取得（MSAAは解決）。
   2. 必要なら深度を取得（L3の効果が有効なときだけ）。
   3. 明るさの順応：縮小した画像から平均輝度を求め、前フレームの値と時定数で混ぜる。
   4. ブルーム：縮小・ぼかし・拡大。
   5. 各 `.fx` のpassを順に実行。
   6. 最終出力。
4. ゲームの状態（時刻・天候・室内か・昼夜の係数）：`.fx` が使う変数の値をENB互換層が供給する。ゲーム内のアドレスは固定版生成物から特定する必要がある（Codex）。特定できない間は、時刻だけ端末の値から近似するか固定値で動かし、その旨を表示する。
5. 差し込み位置：HUDの直前。present-gradeの試作はHUDを含む最終画像に掛けているため、HUD描画の直前の特定は固定版生成物で行う（Codex）。それまではHUD込みの画像に掛ける。

## 5. ENB互換層（`.fx` から見えるもの）

ENBの `.fx` は、次のような名前でエンジンから値と画像を受け取る（所有者のプリセットで名前を確認して表を確定する。ここでは一般的な知識に基づく仮の一覧）。

| 区分 | 例 |
| --- | --- |
| 変数 | `Timer`、`ScreenSize`、`ENightDayFactor`、`EInteriorFactor`、`EBloomAmount`、`AdaptiveQuality`、`Weather`、`TimeOfDay1/2`、`ENBParams01`、`FieldOfView` |
| 画像 | `TextureColor`、`TextureBloom`、`TextureLens`、`TextureDepth`、`TextureAdaptation`、`TextureOriginal`、`TextureMask`、`TextureNormal` |
| UI変数 | `UI_*`、`<string UIName=…>`、`<float UIMin=…>` の注釈（`enbseries.ini` と対応） |

互換層の仕事は、(a) `.fx` の変数と注釈を読んで `enbseries.ini` の値で埋める、(b) ENB固有の変数・画像を供給する、(c) 供給できないものを一覧にする、の3つ。

## 6. 最適化（30 fps前後の目標）

- 予算：ゲーム解像度でのGPU時間の効果全体を、まず約4〜6 msに置く（30 fpsで1フレーム約33 ms、ゲーム本体の描画に残りを残す）。実測で調整する。
- 品質の段階（`quality` 0〜3）：
  - 0：L1の単一パスのみ。
  - 1：ブルーム・順応を1/4解像度、被写界深度なし。
  - 2：ブルーム・順応を1/2解像度、被写界深度は1/2解像度。
  - 3：プリセット本来の解像度。
- 自動調整：直近のフレーム時間（既存の `IOS_PERF`）が目標より長い状態が続いたら品質を1段下げ、余裕が続いたら1段上げる。段階の変更は急に行わず、ヒステリシスを持たせる。端末の発熱（既存の端末状態）も入力にする。
- パスの統合：1画素で完結する処理（色調、トーンマップ、ビネット）は1回の全画面描画にまとめる。
- 中間画像：Apple GPU向けに、使い終わった画像を捨てる（不要な書き出しを避ける）。解像度が同じ画像は使い回す。
- 深度は、深度を使う効果が有効なときだけ解決する。
- 計算は可能な範囲で半精度（MSL生成後に確認）。
- シェーダーの組み合わせ：効果ごとの有効／無効で、使わない処理を実行しない。

## 7. 試験

- Web（Linux）：自作の `.ini` と `.fx` で、解析、変数の供給、パス計画、品質の自動調整、診断の数値を試験する。通常とASan/UBSan。
- Codex：自作の `.fx` をvkd3d-shaderでコンパイルし、DXVK上で実行して画素を参照値と比較する。オフ時の画素一致。所有者のプリセット一括のコンパイル可否の一覧。
- iPhone：同じ場面・同じセーブで、オフとプリセットごとのフレーム時間、メモリ、発熱を比べる。見た目はWindowsの参照画像と並べて確認する（完全一致は目標にしない）。

## 8. 所有者の入力（Web環境にないもの）

- 検証するENBプリセット一式（`enbseries.ini`、`enbseries/*.fx`、画像）と、そのENB本体の版。有名なものを複数。
- WindowsでENBを入れた同じ場面の参照画像。
- 固定版生成物（HUD直前の位置、時刻・天候・室内の値のアドレスの特定に使う）。
- Mac（Xcode、iPhoneOS SDK）と、iPhone 17 Pro Max。
