# PC版のモバイル操作と設定

**2026-11-17の次回候補（実装・PC検証済み、未ビルド・未導入）**：「両手」／`L+R`を追加。押している間は左右のトリガーを同時に入力する。既存LT／RTと同じく短いタップは120 ms保持し、長押しは離すまで継続する。別の指で押しているLT／RTは両手ボタンの解除で取り消さない。タッチ取消ではその入力を即時解除し、設定・配置編集・非アクティブ化では全入力を解除する。ゲーム側の装備・魔法・割り当てを変える機能ではない。

新ボタンも位置・サイズ・不透明度を調整できる。保存済みの配置IDは変更せず、移動スティック18の後に両手19を追加する。初期位置は右側の操作群の左隣。実Cの通常・ASan/UBSan・TSan検査と既存上流への入力適用5検査を通過した。新ボタンを含むApple SDKビルド、実機での見た目・詠唱開始／解除・ゲーム内の両手魔法動作は未確認。

build13の各ボタンは記号＋A/B/LT/RT等の識別表示。設定は歯車、クイック保存は下向き保存アイコン、文字入力はキーボード。Englishが既定で、Languageから日本語を選べる。アプリ言語は即時反映・保存される。ゲーム本文と音声は別の設定で、対応パックの導入と完全再起動が必要。

視点の余分な回転を減らすため、古い80ms固定保持をタッチ周期に応じた短い保持＋減衰へ変更済み。60Hzでは最後の入力から約41.3ms、120Hzでは約24.7msで停止する。連続ドラッグの元の速度と指を離した時の即時解除は維持する。

以下は既存buildの機能説明。未配布の両手ボタンだけは次回候補と明記する。

## 操作

左スティックで移動、ボタン以外の空間をドラッグして視点を動かす。右スティック入力は画面の高さに対する指の移動速度から作り、指を離したときと入力が途絶えたときにはゼロへ戻す。移動・視点・攻撃を同時に操作できる。

| ボタン | 標準割り当ての目安 |
|---|---|
| A / B | 使う・決定 / キャラクターメニュー・戻る |
| X / Y | 武器を構える・しまう / ジャンプ |
| LT / RT | 左手・防御 / 右手・攻撃 |
| 両手 / L+R（次回候補） | LTとRTを同時入力。長押し詠唱にも使用可能 |
| LB / RB | 走る / シャウト。メニューによってタブ切替 |
| 十字キー | メニュー項目・お気に入りの移動 |
| L3 / R3 | 隠密 / 視点切替 |
| START / BACK | システム・ジャーナル / 待機 |

ゲーム内でキー設定を変えた場合はゲーム側の割り当てが優先する。画面の「設定」から感度、上下反転、移動の遊び、サイズ、不透明度を変更できる。「ボタンをドラッグして配置」では各ボタンと移動スティックを移動して保存できる。設定画面自体はゲームを停止しない。必要なら先にSTARTでゲームのメニューを開く。

UIKitで操作画面を描くため、従来の毎フレームのD3D9 state block Capture/Applyと操作パッドの描画呼び出しは不要になる。入力は小さなmutexで保護したスナップショットでゲストに渡す。物理コントローラーの入力経路も維持する。

## セーブ

「クイック保存」はゲーム本来のF5を500ms送信する。DirectInputのキー状態とバッファ付き入力の両方が同じ状態を読む。アプリのプロフィール内のquicksave `.ess` の変更を最大12秒確認し、更新を検出できなければ未確認と表示する。ゲーム側が保存を認めない場面では保存できず、成功を偽装しない。F5が現在のゲームパッド設定でも受け付けられるかは実機確認が必要。

これは実行状態全体を保存するステートセーブではない。現在の静的変換はネイティブCの呼び出しスタックを使い、Win32代替ハンドル、スレッド、GPU・音声にも外部状態がある。ゲストRAMのコピーだけでは復元できない。完全なステートセーブには全スレッドの停止点と再開表現、ホストオブジェクトの再作成、GPU完了点を揃える別設計が必要で、build3では実装していない。

## 画質と発熱

最軽量・パフォーマンス・バランス・高画質・最高画質の5プリセットと、描画解像度、テクスチャ、異方性フィルター、FXAA、MSAA、影の解像度と距離、草と物体の表示距離、水面反射、デカールの個別設定を用意する。これらはアプリ内の `SkyrimPrefs.ini` に選択項目だけを適用し、次回起動から反映する。元のSteamインストールやゲームデータは変更しない。初回は現在の画質を維持する。「維持」は以降の上書きを止める選択で、過去の値を復元する選択ではない。

FPSの追加上限なし／24／30／40／60は即時反映する。待ち時間にはsleepを使い、mainではUIKitを処理し、遅れたフレームを取り戻すための連続描画はしない。上限は達成FPSの保証ではない。高温時の自動抑制は任意で、iOSのthermal stateがseriousなら30、criticalなら24に上限を下げる。正常な状態に戻ると選択した上限に戻る。画質を自動で下げる処理はない。

通常は詳細なAPIログを停止し、重大なエラーと5秒ごとのFPS・熱状態・Present内のホスト待ち時間・最大フレーム間隔を残す。Presentの時間はGPU実行時間そのものではない。FPS向上や発熱低減は実機比較前には確定しない。

## 確認範囲

- Linux上の実C検査：入力の合成、短いタップ、指を離したときの解除、Retina／タッチ頻度によらない視点速度、同時読み書き、F5解除、温度ポリシー、FPS変更と長い停止後の再開。
- Python 5件：固定上流の実コードへ適用し、物理パッド、両Present、現在のINIを維持する経路、CPU ABIの不変、変更されたアンカーの拒否を確認。
- Codemagic build11でUIKitを含むARM64／iPhoneOSのコンパイル・リンクが成功。自作3シェーダーの実Metalコンパイルも成功。既存private guestと共有するCPUヘッダー3ファイルはbuild2と一致する。
- 実機の同時タッチ・メニュー・保存確認・画質反映・温度／FPS比較は別途必要。上記のPC／SDK検査で実機合格とは扱わない。
