# Skyrim LE DLL compatibility experiment

The optional MOD screen checks a DLL or a MOD folder selected from Files. Installed MODs also have a diagnostic action in their details. The check runs the SKSE initialization exports in an independent, bounded x86 interpreter. The result applies to initialization and the two data-free startup notifications inside that test environment.

The PE32 loader validates the x86 layout, section permissions, exports, import ownership and HIGHLOW relocations. Its mapped sections and temporary stack are ordinary data. A small table of virtual addresses provides the Classic SKSE release index and plugin handle, registration for `PostLoad` and `PostPostLoad`, Windows uptime, CRT memory operations and a bounded virtual heap. The interpreter supports common repeated copies and stores on checked memory ranges. Unsupported imports, formats, instructions and SKSE calls have distinct results. Instruction count, bulk work and file/image sizes have explicit limits.

For a MOD folder the diagnostic scans the selected directory and its `SKSE/Plugins` and `Data/SKSE/Plugins` directories. It resolves up to three supporting DLLs for each plugin using their file and exported function names. Shared dependencies are initialized once. The loader chooses disjoint virtual addresses when the preferred addresses overlap. Selection is limited to 16 files and 64 MiB. The diagnostic reports missing, ambiguous and cyclic dependencies before initialization.

The emulated Windows calls include private memory allocation, thread-local values, last-error state, recursive critical sections and 32-bit Interlocked operations on a single logical thread. Each DLL with static TLS gets its own initialized block. Its process attach and detach callbacks run in Windows order inside the same bounded diagnostic. A read-only scan of Classic JContainers 3.3.0 found 181 imports and static TLS. It still needs file APIs, Windows threads and additional SKSE interfaces before a gameplay trial. When an import has no binding, the screen names the Windows function or helper so users can identify the exact blocker.

Plugins can also resolve approved names from the virtual `kernel32` and `msvcrt` libraries. Both named and static lookups use the same service table. Module handles and function addresses are diagnostic values. The application never opens a Windows system DLL to resolve these calls.

The folder diagnostic can supply read-only file snapshots to these calls from the selected MOD. The VM understands relative paths, including UTF-16 names, and reads each file into an immutable payload before exposing a virtual handle. A diagnostic can hold four files open, read up to 1 MiB per file and open 4 MiB in total. Synchronous reads, file sizes, end-of-file and handle closure use the Windows ABI. A file chooser that grants a single DLL does not grant its folder. Path lookups use the selected filesystem's spelling rules.

The experimental event services track unnamed manual-reset and auto-reset events in the same virtual process. They preserve signal consumption across single-event and multiple-event waits. Polling and already-satisfied waits are supported. An alertable wait or a wait that needs another Windows thread is reported as unsupported.

The Classic v4 serialization trial can run one DLL's registered save, revert and load callbacks against authored records kept in memory. It checks stream writes, partial reads, skipped record tails and end-of-stream without opening a saved game. Resolving a real form or handle and delivering a game-object deletion require the live game catalog and events.

The app option `SKYRIM_IOS_SKSE_DLL_PROBE` defaults to OFF. In an experimental build, open Settings → MOD → Details → DLL Compatibility. Remaining work includes plugin gameplay, broader Windows support, engine interfaces and ENB rendering. The diagnostic runs only when opened, outside the ordinary rendering path.

The tests generate their own DLLs. On Windows, `python -B -m unittest -v test_pe_image test_skse_plugin_vm test_dependency_plan` compares interpreted initialization to authored DLLs run by Windows, including relocations, allocated memory, thread-local values, callbacks and the attach and detach order of a four-DLL package. On Mac, `bash test-apple-sdk.sh` also checks the iPhoneOS sources and runs the same UI controller in an iOS simulator. It supplies selected URLs to the document picker's delegate and verifies the isolated diagnostic results in English and Japanese. Physical Files providers and gameplay need separate tests.
