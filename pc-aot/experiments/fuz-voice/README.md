# Fuz Ro D-oh LE voice fallback

This hosted experiment evaluates a single Skyrim LE dialogue response. A caller supplies the game's original WAV candidate, a resource lookup and the installed stock clip names for one through ten seconds. The fixture supplies these names from memory. It checks selection and subtitle decisions on Windows and POSIX.

## Classic 6.1 evidence

The Nexus LE release lists 6.1 for TESV 1.9.32.0. Its description labels the main readme text 6.0 and records the empty-response setting in the 6.1 changelog. The author's Win32 source identifies its version as 6.1 and checks the LE runtime. The pinned repository carries GPL version 3. The separate Special Edition repository targets SKSE64 and includes newer text handling. [LE files](https://www.nexusmods.com/skyrim/mods/14884?tab=files) · [LE readme](https://www.nexusmods.com/skyrim/mods/14884?BH=2) · [LE version resource](https://github.com/shadeMe/Fuz-Ro-D-oh/blob/17092b2562e4fff422448bcf2ee9d0a42b995806/VersionInfo.h#L16-L17) · [LE license](https://github.com/shadeMe/Fuz-Ro-D-oh/blob/17092b2562e4fff422448bcf2ee9d0a42b995806/LICENSE) · [SE repository](https://github.com/shadeMe/Fuz-Ro-D-oh-64)

LE 6.1 tests the original WAV, FUZ and XWM via the game resource stream. Missing ordinary speech uses integer division of the count of space-delimited words by the configured rate, adds one second and caps the result at ten. The default rate is two. Short or `<ID=` responses use two seconds when eligible for substitution. The original substitution condition reads the tokenizer's final output, so a one-byte final token can suppress substitution. A single space uses the two-second clip only when the empty-response setting allows it. [LE resource and subtitle implementation](https://github.com/shadeMe/Fuz-Ro-D-oh/blob/17092b2562e4fff422448bcf2ee9d0a42b995806/FuzrodohInternals.cpp#L99-L269) · [LE-era tokenizer](https://github.com/shadeMe/SME-Sundries/blob/b0bed242ced83f7e0a2c3153197af9ebfd7eae6b/StringHelpers.h#L29-L46)

The experiment returns as soon as any original voice is present. The lifted assignment validates the response header up front and only copies its text after the original voice candidates are all absent. If the header changes during resource lookup, the assignment leaves the original path in place. A resolvable stock path is required for substitution. The returned subtitle decision applies to the current response. An explicit topic force flag is preserved, and automatic forcing requires an eligible response with a selected stock clip. This avoids sharing a subtitle mark between separately voiced and unvoiced responses that have identical text.

## Hosted call-site experiment

The reviewed Classic lift contains the `StringCache::Ref::Set` call with guest return address `0x0067326D` in `f_6731A0`. The containing function owns the 260-byte path buffer on its guest stack. It zeroes and fills that buffer before the call. The response begins with an eight-byte Classic `BSString`. The hosted adapter copies both inputs through a checked memory interface and commits a replacement only when the complete stack buffer still matches the snapshot. The selected clip comes from the supplied owner catalog.

`stage_lift.py` checks the private generation metadata, source unit hash and single call anchor. It writes a new scratch copy with one hook call before the original assignment. The hosted fixture uses an authored assignment callee to verify the original call runs once after the hook and restores the expected stack pointer. When enabled, the private fixture also syntax-checks the complete staged unit and runs its exact call line in the hosted fixture. The following fixtures exercise resource lookup and the two subtitle paths separately. App integration and device playback with an owner-installed LE package remain.

Run from this directory with `python3 -B -m unittest -v test_voice_fallback`. Set `SKYRIM_TEST_SANITIZERS=1` for a supported ASan and UBSan compiler.

Set `SKYRIM_TEST_OWNED_CLASSIC_LIFT` to the reviewed local generation directory to include the private call-site fixture. To stage the unit independently, run `python3 -B stage_lift.py <private-generation> <new-scratch-file>`.

## Hosted resource lookup

The optional private resource test compiles the reviewed resolver entry, the two input-stream constructors, the reference increments and decrements, the close wrapper and the deleting destructor. It stages seven routines from five checked translation units. An authored catalog handles the engine lookup and stream callbacks inside committed fixture pages. The fixture verifies the original read-mode arguments, raw resolver return status, open validity, disposal after a stream-open failure and preservation of the fixture's stream and caller positions. Unknown callback targets, including reads or seeks, fail the test.

The Classic response resolver sends each candidate name separately. Its cache key carries the extension in a separate field and the sound resource registration path recognizes WAV, FUZ and XWM. The original LE 6.1 DLL assigns an `.xwm` name, while its ten bundled stock clips are `.fuz` containers with lip data. The app checks the `.xwm` name first, checks the matching `.fuz` if it is missing and assigns the original `.xwm` name when either resource is present. A resource I/O error leaves the response untouched. Hosted tests exercise the names independently and verify the assigned path. The game still needs to be checked for alias resolution, actual playback and lip movement. [LE stock path construction](https://github.com/shadeMe/Fuz-Ro-D-oh/blob/17092b2562e4fff422448bcf2ee9d0a42b995806/FuzrodohInternals.cpp#L137-L206)

## Game resource lookup connection

`lift_resource_lookup.c` builds the reviewed Classic `BSIStream` using the caller's CPU state, reads the stream and valid fields, then destroys it in place with `f_B08970` and flag 0. Its caller supplies the exact live stack pointer, a verified writable interval owned by the current thread and the allowance for nested calls. Both the scratch frame and the original path buffer must fit before the hook runs the lookup. A recursive request on the same host thread is refused, and destruction requires the reviewed object type. The staged constructor passes its CPU to `skyrim_fuz_host_choose_menu_voice` for the future app adapter.

The original LE 6.1 policy treats a null stream as absent. A stream present with a failed open is a lookup error and keeps the original path. `f_B08530` discards the resolver return code after testing for zero. The pinned loose-file resolver also reports failed attribute queries as missing, so logging the upstream result would still leave some I/O failures indistinguishable from absent files. An app integration that requires verified absence needs evidence from the mounted resource sources.

`test_guest_lookup.c` checks the provider with authored stand-ins. It tests the owned stack and nested-call allowance, preserved CPU state, reentry, type validation and the original voice and subtitle decisions. The private resource test uses dedicated committed stack pages to run the same provider against the pinned construction and cleanup routines. It verifies that flag 0 skips freeing the outer stream object while its references are released. The fixture's stack allowance applies to its authored resource backends. The app still needs to establish the allowance and the lifecycle of its real callbacks.

## Subtitle ownership in the reviewed lift

The dialogue-menu queue `f_8980D0` receives one text argument. One caller in `f_6758A0` reaches the selected response through the menu's `lastSelectedResponse` and its `+0x20` cursor before extracting text at return address `0x00675CAA`. Other direct callers at `0x00675C06` and `0x00567AEE` pass text from `f_6FB910`, which returns the actor-process string at offset `+0x198`. The final text argument alone cannot identify the response whose voice path was assigned.

In the world path, `f_4DFBF0` reads the same current response's `+0x10` voice path and `+0x0` text before queuing it at return address `0x004DFDDD`. The caller can reuse actor-owned dialogue data, and `f_672AA0` advances the response cursor. Queue creation `f_8929A0` and copying `f_8929E0` preserve the existing force byte at `+0x10` of a 20-byte chatter record. The record owns copied text and stores the actor handle, distance and force byte. The world display tests the force byte before the normal distance check, then checks the subtitle settings separately.

These findings distinguish the direct response path from actor-derived menu and world messages. The hosted fixture below carries the selected response's decision to the direct menu queue. [LE subtitle hooks and force rules](https://github.com/shadeMe/Fuz-Ro-D-oh/blob/17092b2562e4fff422448bcf2ee9d0a42b995806/FuzrodohInternals.cpp#L229-L385)

## Hosted selected-response subtitles

The cache constructor `f_6731A0` assigns the selected voice path to `CachedResponseData + 0x10` through the original string-cache call. The host only marks a response after the assignment points to the exact accepted eligible stock path. Two allocation callers insert the resulting 36-byte guest object into response lists. The alternate constructor and save-data load clear any stale mark. List teardown `f_672EA0` clears the mark before it releases the string-cache reference and frees the response. The fixture records the exact guest object, interned path reference and a host serial. It holds at most 64 active marks and leaves additional responses on the normal subtitle path. [Classic LE response and menu layouts](https://github.com/shadeMe/Fuz-Ro-D-oh/blob/17092b2562e4fff422448bcf2ee9d0a42b995806/FuzrodohInternals.h#L145-L216)

The privately staged direct menu caller at `0x675CAA` supplies one synchronous selection scope. The queue verifies the menu selection, list cursor, response, voice reference and argument again after it reads the original subtitle setting. It admits an eligible marked response or the selected topic's explicit force flag. It checks that the guest text is a complete bounded string before entering the original queue path. Other callers continue to use the ordinary entry, including actor-derived menu messages. The world chatter gates and distance checks are independent.

The hosted test runs the original selected tail, the modified setting gate, the lifted string copy and the normal deferred queue insertion. The heap, string-cache service and queue notification use authored data. A separately voiced object can share both the exact text and the exact stock-string pointer and still receive no automatic subtitle. The test also covers a cursor change, reused response address, a failed assignment and an original queue allocation failure. The actual lifted list teardown runs before the test checks that the enqueued title still owns its copied bytes.

The private test syntax-checks all three staged units and uses the pinned source hashes before generating any temporary source. App resource lookup, the actual notification consumer, simultaneous dialogue callbacks, dialogue queue overflow and device playback remain to verify.

## Hosted world chatter subtitles

`stage_world_lift.py` captures the accepted response serial immediately before the original sound submission at `0x004DFD0B`. The fifth argument to `f_B9CA90` is the submitted voice reference. The original chatter call at `0x004DFDDD` must carry the same response's validated title and still match that serial. This permits the original `f_892CE0` admission when both subtitle settings are off. The actor, title validation and original force-byte checks retain their existing order.

The original `f_892C90` reserves a row and calls `f_8929E0`. The tracker marks the row only when that call creates a distinct, validated heap copy of the selected title. The published identity is the array descriptor and owned title allocation. It survives movement of the rows and the destruction of the original response. A fresh copy invalidates any prior mark for its allocation. The range destructor, direct remover and update loop retire marks before the title frees at `0x00696413`, `0x00892F55` and `0x00893173`. The tracker holds at most 64 active chatter marks.

`f_892AB0` applies the optional override only at the general subtitle switch at `0x00892B1D`, after the normal range and duplicate speaker decisions. The game's original force byte, range and dialogue path are preserved. The runtime path and fixture assume serialized guest callbacks.

The hosted test stages the original audio submission caller, world record admission and copy, spatial and duplicate-speaker checks, all three title free anchors and the array reset. The original array allocator and grow routine move the old rows and retain their independently allocated titles. Authored engine dependencies supply sound, actor and heap behavior. Tests cover both settings off, corresponding voiced lines with identical text and voice pointers, a replaced response during sound submission, the original force path, failed title and array allocations, slot reuse, movement and reset. The test stops at the subtitle display decision. The device adapter, real HUD consumer and playback remain to verify.
