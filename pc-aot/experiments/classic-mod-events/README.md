## Source contract

Classic 1.7.3 registers static, NoWait `ModEvent.Create(string) → int`, `PushBool(int, bool) → None`, `Send(int) → bool` and `Release(int) → None`. `Create` stores an event name and the creating stack. Positive object handles are one-based storage slots. A freed index is reused in last-in-first-out order. `PushBool` appends in call order. `Send` takes the event out of that slot before any delivery. It returns true for a valid event even without recipients. `Release` consumes without delivering. The stack is used to collect dropped objects before saving. Classic does not check the calling stack again on push, send or release. [Classic SKSE source archive](https://skse.silverlock.org/)

Classic `PapyrusModEvent.cpp` and the older `Form.SendModEvent` share `g_modCallbackRegs`. The registration map uses the interned event name. It stores the registered callback per full 64-bit recipient handle and visits receivers in ascending handle order. `ModEvent.Send` supplies only the packet's typed arguments. The legacy sender supplies event name, a string, a float and a sender. The pinned Skydream runtime already has legacy send and registration for `Form`, `Alias` and `ActiveMagicEffect`. Its native descriptor table lacks the static `ModEvent` methods. The control-event experiment uses a separate audience and control payload. [Pinned Skydream descriptors](https://github.com/meizfl/skydream/blob/ecf814f58292d70ad5cfb19a5c61b5d8d8006a4a/runtime/skse_compat_values.c) · [Pinned delivery source](https://github.com/meizfl/skydream/blob/ecf814f58292d70ad5cfb19a5c61b5d8d8006a4a/runtime/skse_system.c) · [Control event experiment](../classic-control-events/README.md)

The original LE registry published by `f_C33360` uses vtable `0x114C1B0`. Slot 35 calls `f_C4C160`, which finds the target script objects and calls slot 38 `f_C4FCE0` at `0xC4C2F9`. For an accepted ordinary script callback, `f_C4FCE0` invokes `IFunctionArguments::Copy` at `0xC4FE03` before constructing the queued event in `f_C57BB0`. That constructor copies the callback name with `f_A50D50` and uses `f_C56DB0` to copy the VMValues with `f_C329E0`. The sender can destroy the temporary argument object when that `QueueEvent` returns.

## Hosted fixture

`mod_event.c` implements one VM owner's bounded boolean packet storage. It copies the event name on creation and the packet on send, before freeing the slot. It keeps the original positive slot and reuse semantics inside one epoch. The explicit owner epoch, 32 slots, 255-byte names and 16 boolean arguments are limits of this experiment.

The test stages the pinned Skydream `send_event` and `event_copy` with the existing legacy sender. It supplies authored registrations and a VM queue that copies through the staged argument vtable and owns the queued names and values after the send returns. The same registrations show that the typed sender reaches the named callbacks with only its boolean or empty payload and the legacy sender still emits four values. The test checks ordered full-width handles, another registry's exclusion, successful consumption with no listeners or failed queue copy, same-slot reuse, invalid handles, capacity and stack cleanup. The original queue stages are checked against the pinned private lift. Guest allocation, queue release and the VM epoch transition are authored.

The retirement case leaves one event in the old VM queue and one unsent packet in the old object table. It checks both remain valid in the old epoch, then releases the queued name and values and clears the packet and registration state. With the same registry address, receiver handle and packet slot in the next epoch, it rejects the old packet and a stale registration row. Only the accepted epoch's callback receives the new value. The old queue is disposed of without sending another event or invoking a retired handle policy.

## Profile selection and VM retirement

The profile picker writes `state["next"]` via `SaveState` and leaves `activeProfile` live. `skyrim_mods_select_profile` sets the active profile at the next process startup. `ios_entry.m` resolves the profile directory and prepares the game view before invoking the guest. A successfully saved selection therefore takes effect in a fresh process. The picker or a return to the foreground does not retire the current VM. [Profile picker and startup selection](../../ios/runtime-port/mod_manager.m) · [Guest startup](../../ios/runtime-port/ios_entry.m)

An ordinary load or script reload can revert a VM within the same process. Classic calls the original `f_8D5DF0` at `0x8D69A7` and `0x8D6E16` before its serialization revert callbacks. `Core_RevertCallback` clears `g_modCallbackRegs` and clears persistent object storage without releasing each registration through the retired policy. `Core_LoadCallback` later restores `MCBR` registration records and `OBMG` objects. The pinned Skydream registration list has no matching revert integration. [Classic SKSE source archive](https://skse.silverlock.org/) · [Pinned Skydream registration list](https://github.com/meizfl/skydream/blob/ecf814f58292d70ad5cfb19a5c61b5d8d8006a4a/runtime/skse_system.c) · [Accepted load fixture](../classic-fresh-load/README.md)

A live producer needs the actual native stack ID, accepted VM epoch and running profile. The event pump and snapshot acquisition must serialize with VM retirement. Finish any synchronous queue copy under its live owner. After the verified original revert, discard host rows and pending objects without using the old policy. Reopen delivery only after the new accepted VM scope is available, and restore rows only from its verified profile and save generation. A failed save-file selection before a revert supplies no retirement signal. Sharing or restoring `OBMG` alongside other Classic object classes still needs a typed storage owner. Ordinary app registration and iPhone meter behavior remain unverified.
